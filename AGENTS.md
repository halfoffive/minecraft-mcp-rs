# minecraft-mcp-rs — MCP server that controls a Minecraft bot

An MCP (Model Context Protocol) server backed by an actual Minecraft bot via the azalea library. Exposes bot capabilities (movement, block manipulation, inventory, combat, chat) as MCP tools consumable by LLM clients. Ships with an egui desktop UI for status and settings.

- **Stack:** Rust nightly (edition 2024; azalea 0.15.1's build script requires nightly), azalea 0.15.1 (Minecraft 1.21.11 bot — the ONLY supported Minecraft version), rmcp (MCP server), egui/eframe 0.34.3 (desktop UI), tokio 1.50 (async runtime), bevy_ecs 0.18 (azalea's ECS), schemars 1.0 (MCP JSON schemas), proptest (property testing)
- **Entry point:** `src/main.rs` — creates shared state + channel, spawns MCP server on background thread + egui on main thread. Bot connection is spawned on a dedicated OS thread from the UI (azalea's `ClientBuilder::start` internally creates a `LocalSet` which is `!Send`, preventing `tokio::spawn` on a multi-threaded runtime).
- **Library crate root:** `src/lib.rs`

## Development workflow

**默认流程：任何修改都在新分支上进行，提交 Pull Request，经用户审阅通过后合并。分支模型（详见 `CONTRIBUTING.md`）：`develop`（集成）→ `release`（预发布通道，push 即自动预发布）→ `master`（稳定版，tag 即稳定发布）。**

1. **建分支** — 功能/修复/文档分支从 `develop`（或已同步的 `master`）创建，命名建议：`feat/<slug>`、`fix/<slug>`、`docs/<slug>`。禁止直接向 `master` / `release` 提交；**禁止使用 `release/<X.Y.Z>` 分支名**（git refs 命名空间与 `release` 分支冲突，按版本准备分支改用 `hotfix/<X.Y.Z>` 等前缀）。
2. **开发** — 遵循下方「Conventions」与「规范」：`cargo fmt` → `cargo test`（全过）→ `cargo clippy --all-targets`（零警告）→ 更新 `README.md` / `CHANGELOG.md` / `AGENTS.md`。
3. **提交** — 按 S-16 的原子提交拆分（CI → AGENTS.md → Cargo+npm → markdown 引脚/表 → CHANGELOG），每条提交只做一件事。
4. **PR** — `git push -u origin <branch>` 后用 `gh pr create` 提交 PR（默认目标 `develop`），PR 描述写明改动内容、验证结果（`cargo test` / `clippy` 输出）、影响面（含 wire 破坏性变更）。**必须等待用户审阅。**
5. **合并** — 用户审阅（可能要求修改）通过后合入 `develop`。
6. **预发布**（`release` 分支）— `develop` → `release` 的 PR 合并后，在 `release` 上把版本改为 `X.Y.Z-rc.N`、跑 `node npm/scripts/sync-versions.mjs`、补 CHANGELOG `[X.Y.Z-rc.N]` 节并 push：`release.yml` 自动发布**预发布版**（GitHub prerelease + npm `next`）。
7. **稳定发布**（`master`）— `release` → `master` 的发布 PR（版本定稿 `X.Y.Z`、更新 markdown 引脚/兼容表、CHANGELOG 定稿）合并后，在 `master` 打 `vX.Y.Z` tag：自动发布**稳定版**（GitHub Latest Release + npm `latest`）。随后 `master` 快进合并回 `develop`。

例外：用户在本会话中**明确指示**直接提交/直接发布时，可跳过分支+PR（例如一键发布指令）；否则一律走分支+PR。

## Architecture

Layered: **types → logic → state → bot → mcp → ui**, all in one crate.

```
src/
  types.rs            — Shared data types (BlockPos, BotCommand, WorldSnapshot, etc.)
  error.rs            — BotError enum (actionable error variants for AI agents);
                        re-exports BlockPos/ToolType/MaterialTier from types.rs
  config.rs           — AppConfig (UI settings) + RunStats (atomic counters)
  state.rs            — SharedState (thread-safe hub: ArcSwap for snapshot, RwLock for config,
                        AtomicBool for online/connecting/disconnect flags)
  block_data.rs       — Block/tool/material tables, best-tool selection
  mining_calc.rs      — Mining time formulas (the single canonical calculate_mine_time)
  command_validate.rs — Coordinate validation and command pre-checks
  snapshot.rs         — World snapshot data structures and chunk summaries
  tool_select.rs      — Best-tool selection logic
  utils.rs            — Common utility helpers (e.g. `to_snake_case`,
                        `contains_ascii_case_insensitive`)
  compound_ops.rs     — Compound operations (e.g. mine-and-collect pipeline)
  channel.rs          — Cross-thread BotCommand channel (tokio mpsc + oneshot);
                        ReceiverSlot + ReceiverLease for executor lifecycle
  i18n/               — UI internationalization (functional, one file per
                        language; lives at crate root so both ui/ and mcp/ can
                        use it without an mcp→ui dependency)
    mod.rs            — Language enum, TextKey enum, thread-safe current()/set()/tr()
    en.rs             — English lookup table
    zh_cn.rs          — Simplified Chinese lookup table
  logging.rs          — tracing-subscriber setup (stderr only; stdout = MCP transport)
  bot/                — Minecraft bot lifecycle
    mod.rs            — Re-exports
    connection.rs     — ConnectionManager (connect, reconnect with backoff, disconnect)
    events.rs         — azalea event handlers (player position, chunk loads, chat)
    commands.rs       — BotCommand → azalea action execution
    ops.rs            — Higher-level bot operations (move, mine, place, etc.)
    snapshot_updater.rs — Periodically snapshots world state into SharedState
  mcp/                — MCP server
    server.rs         — McpBotServer (rmcp ServerHandler), stdio or HTTP transport
    tools_*.rs        — Tool definitions organized by domain: query, movement, block,
                        item, container, combat, chat, plus unified `act`
    render.rs         — Top-down PNG world rendering for `get_world_view`
  ui/                 — Desktop UI
    app.rs            — egui app shell
    fonts.rs          — CJK system font auto-detection + injection into egui FontDefinitions
    settings.rs       — Settings panel (includes MCP transport / port / token / language)
    status.rs         — Status panel with live stats
    mcp_config.rs     — Copyable, live-generated MCP client JSON config
tests/
  integration.rs      — Mock-based end-to-end tests (no real MC server)
  proptest.rs         — Property-based tests for block_data, command_validate
```

## Conventions

- **Doc comments (`//!`)** on every module, doc comments (`///`) on every public type and function.
- **Section separators:** `// ═══`, `// ----`, or `// ≡≡≡` lines between logical sections within a file.
- **Error handling:** `BotError` (thiserror) for all bot/MCP errors; `eyre` for rarely-needed error context (no `anyhow` dependency).
- **Thread safety:** `Arc<SharedState>` shared across threads; `ArcSwap` for lock-free snapshot reads; `RwLock` for config/stats; `AtomicBool` for online flag; `Mutex` for container handle and chat messages.
- **Testing:** Unit tests in `#[cfg(test)] mod tests { .. }` at bottom of each source file; integration tests in `tests/`; property tests with `proptest` crate.
- **Logging:** `tracing` crate macros only; all output to stderr (`stdout` reserved for MCP JSON-RPC transport). Enabled via `init_logging()` called once at startup.
- **Naming:** Types PascalCase, enums PascalCase, functions/methods snake_case, module file names snake_case.
- **MCP tools:** Each tool module (tools_*.rs) exposes a builder function; tool parameters annotated with `#[derive(schemars::JsonSchema)]`.
- **Formatting:** No `.rustfmt.toml` — uses default `rustfmt`.

- **`execute_command` feedback detection (1.1.5):** `handle_execute_command` is now async: it records the chat baseline, sends the command, waits `COMMAND_FEEDBACK_WAIT_MS` (400 ms), then diffs new **System** messages via `server_feedback_after` and matches them against the `is_command_rejection` patterns (`Incorrect argument for command` / `Unknown or incomplete command` / `Unknown command` / `You do not have permission to use this command` / `You are not allowed to use this command` / `Cannot execute`). A hit returns `BotError::CommandRejected { command, feedback }` (-32009, `reason: command_rejected`, retryable); otherwise success is reported with the newest System feedback attached to the message/data. Player messages are never treated as server feedback.
- **Snapshot force-refresh (1.1.5):** `get_self_info(force=true)` / `get_inventory(force=true)` / `get_server_info` / `collect_items` request an immediate snapshot rebuild via `SharedState::request_snapshot_refresh() -> oneshot::Receiver<()>` (single-slot: a new request drops the previous one). `handle_tick` polls `take_snapshot_force_requester()` **before** the throttle gate; when present it skips the interval check and the build task signals the receiver. `refresh_snapshot_and_wait` (`tools_query.rs`) bounds the wait at 3 s and falls back to reading the current snapshot. The `force` params default to `true` (serde `default_true`) so existing callers get fresh reads.
- **`commands_enabled` probe merge (1.1.5):** `get_server_info` sends `BotCommand::ExecuteCommand("/seed")` (3 s bounded via the command channel) when `refresh=true` or no probe result is cached: `Ok` → `set_commands_probe(Some(true))`, `CommandRejected` → `Some(false)`, other errors keep the previous value. `build_snapshot_inner` resolves `commands_enabled` via `resolve_commands_enabled` = probe result `.or_else(PermissionLevel heuristic)` so snapshot builds merge the probe. Response includes `bot_busy` (`SharedState::executor_busy`, set by `run_with_lease` around each dispatch).
- **Movement timeout partial results (1.1.5):** `handle_move_to` / `handle_smart_move` / `handle_fly_to` route `goto` through `goto_with_margin`, which wraps `BotActions::goto` in `tokio::time::timeout(timeout - MOVEMENT_REPLY_MARGIN(1s))` so the executor replies **before** `send_command`'s envelope timeout fires. On timeout it calls `stop_pathfinding()` (new `BotActions` method) and returns a `BotResult` with `{reason:"timeout", position, start, target, distance_moved, distance_xyz, timeout_secs}` instead of a bare `CommandTimeout`. `RealBotClient::stop_pathfinding` = `client.stop_pathfinding()`.
- **`drop_item` verification (1.1.5):** `handle_drop_item` reads `inventory_entries()` before/after the throw-click (250 ms wait): `removed >= count` → success with `{verified:true}`; empty-after-nonempty-before → success with `container_window_open:true` caveat; slot unchanged → `success:false` (empty slot vs server-rejected click are distinguished in the message). The mock `drop_item` now mutates the inventory so the branches are unit-testable.
- **`set_hotbar_item` / `MoveItemToHotbar` (1.1.5):** `BotCommand::MoveItemToHotbar(hotbar_slot, item_id, count)` finds the first inventory slot with `item_id` and count ≥ requested, maps the logical index to a player-menu slot (hotbar 0-8 → 36+slot, main 9-35 → identity) and issues `SwapClick { source_slot, target_slot }` via the new `BotActions::swap_hotbar` (`RealBotClient` guards on `get_inventory().id() == 0` — a container window makes the swap target the wrong menu). The handler verifies the hotbar slot afterwards; missing item → `InvalidParams`. Cannot conjure items.
- **Corpse filter (1.1.5):** `collect_entities` skips entities whose `Health` component is `Some(h)` with `h <= 0.0` — a killed mob lingers in the ECS until the server's RemoveEntities/despawn cleanup, so it previously showed up with `health: 0.0`. Item entities (no Health) are unaffected. Test: `test_collect_entities_skips_dead_entities`.
- **`ObstacleInfo` (1.1.5):** `smart_move`'s `obstacle` payload is now `{block_type, x, y, z}` (serialized via `obstacle_to_json`) instead of a bare string — a breaking wire change. `find_obstacle_block` scans the interpolated XZ line across three Y layers (y, y+1, y-1) then falls back to a 3×3×3 neighbourhood around `current`; `None` only when no solid block is found anywhere.
- **Run-stats accounting (1.1.4):** `CommandExecutor::dispatch` is a thin wrapper around `dispatch_inner` that increments `RunStats` (`commands_processed` + `commands_succeeded`/`commands_failed`) on **every** command reaching the executor — including compound-op sub-commands and validation/offline rejections (the UI panel reports "received commands"). The atomics use `Ordering::Relaxed`. Regression tests: `test_dispatch_records_success_in_run_stats` / `test_dispatch_records_failure_in_run_stats` in `bot/commands.rs::tests`.
- **HTTP shutdown (1.1.4):** `serve_http`'s graceful shutdown races the `shutdown_token` against `tokio::signal::ctrl_c()` via `shutdown_signal` (`src/mcp/server.rs`). Ctrl+C now exits cleanly in every mode — in particular headless mode with the default HTTP transport, which previously deadlocked (the token was only triggered after `serve_http` returned, and `serve_http` only returned after the token fired). UI/stdio paths are unchanged. Test: `test_shutdown_signal_returns_on_token_cancel`.
- **`update_from_tick` → `build_and_store` (1.1.4):** `SnapshotUpdater::update_from_tick` (which cloned the whole snapshot just to return it) was replaced by `check_and_update_timer()` (pure throttle check, no reset side effects for callers) + `build_and_store(&bot) -> bool` (moves the snapshot into `SharedState`, returns whether a repaint is due). `handle_tick` runs the throttle check **before** spawning the build task, so throttled ticks (~18 of 20 per second) no longer spawn a wasted task.
- **`SnapshotBuilder` production constructor (1.1.4):** `SnapshotBuilder::new(old_blocks: Vec<BlockEntry>)` is the per-tick path — it carries over **only the block list** (not the old snapshot, whose `block_index` HashMap and unused fields used to be deep-cloned every 500 ms). Unset fields fall back to `WorldSnapshot::default()`. `SnapshotBuilder::from_old(old: WorldSnapshot)` keeps the old full-snapshot semantics for tests. The per-tick caller must supply every field via `with_*` (it does).
- **Block-name cache (1.1.4):** `block_state_to_name` resolves each distinct `BlockState` id once into a `LazyLock<Mutex<HashMap<BlockState, String>>>` cache instead of paying `format!` + `to_snake_case` per block per tick. `BlockState` is a `Copy` `Hash` u16 wrapper.
- **`contains_ascii_case_insensitive` (1.1.4):** `src/utils.rs` hosts the non-allocating ASCII substring matcher; `get_nearby_blocks` uses it per block instead of `block_type.to_lowercase()` (which allocated per block).
- **`AttackEntity` snapshot guard (1.1.4):** `handle_attack_entity` rejects a target missing from the world snapshot with `BotError::InvalidParams` before attacking (the MCP layer already enforced the same check). Tests: `test_attack_entity_missing_from_snapshot_rejected`.
- **规范:** 函数式编程，大量注释。写完后使用`cargo fmt`格式化；及时编写`cargo test`自动化测试，`cargo test`全过才能交付，编写遵循TDD；需要运行`cargo clippy`检验，全过才能交付；最后更新`README.md`、`CHANGELOG.md`和`AGENTS.md`。**提交走「Development workflow」：默认在新分支上修改，提交 PR 并经用户审阅合并，禁止直接推 `master`；用户明确指示直接提交/发布时除外。**
- **Settings panel:** Uses `EditConfig` local edit buffers (in `app.rs`); fields rendered via `TextEdit::singleline`/`DragValue`. Edits applied to `SharedState` only on Connect. The `sender` parameter was removed from `settings_panel` — the UI doesn't send commands directly.
- **MCP Config panel:** Renders a copyable JSON config (with the executable's absolute path resolved at runtime) for MCP clients like Claude Desktop / Cursor. Uses egui 0.34.3's clipboard API; schemars 1.0 `Schema` (via `schema_for!`) drives any schema rendering.
- **Bot connection:** Spawned on dedicated OS thread (not `tokio::spawn`) because `ConnectionManager::connect()` contains `LocalSet` which is `!Send`. The thread's `JoinHandle` is held by `MinecraftApp` and joined on `Drop` for clean exit. `Drop::join` has a 3-second timeout so closing the window never hangs.
- **Command executor:** Wired into `Event::Spawn` via `spawn_local`. The command receiver is stored in a `ReceiverSlot` (`Arc<Mutex<Option<BotCommandReceiver>>>`) and leased out via `ReceiverLease` on Spawn; when the executor is aborted on `Event::Disconnect`, the lease drops and returns the receiver to the slot for the next reconnect. `Event::Disconnect` also writes `AppExit::Success` to the ECS (`bot.ecs.lock().write_message(AppExit::Success)`) so `ClientBuilder::start` returns and the connect loop can retry (azalea 0.15.1 removed `Client::exit()`).
- **Connect/Disconnect:** `SharedState` has `bot_connecting` (AtomicBool) and `disconnect_requested` (AtomicBool) flags. `try_begin_connecting` guards against double-spawn. `request_disconnect` tells the reconnect loop to stop; the Disconnect button sets it. `clear_connecting` is called when the connect loop exits. A `CancellationToken` (from `tokio-util`) is stored in `SharedState` and cancelled on disconnect so the reconnect backoff sleep returns immediately instead of blocking shutdown. **`ClientBuilder::start()` is wrapped in `tokio::select!` with `cancel_token.cancelled()`** so a disconnect request during the TCP connect attempt (~5 s) aborts immediately via `break` instead of waiting for `start()` to return (variable name `start_cancel` to avoid shadowing the later `cancel_token` locals used for backoff/retry sleeps).
- **Console window on Windows:** `src/main.rs` no longer carries the crate-level `#![cfg_attr(not(debug_assertions), ...)]` attribute that used to hide the console on release builds — it was removed so **release builds keep the console window too**. The console carries `tracing` logs (stderr) and, in `--stdio` headless mode, the MCP JSON-RPC transport, so hiding it on Windows made headless/stdio diagnostics impossible. All builds now show the console on Windows.
- **Connection errors:** `SharedState::last_error` (behind a `Mutex<Option<String>>`) surfaces the most recent connection failure to the UI; the Status panel renders it in red. Connection failures are fail-fast — the reconnect loop stops retrying so the user sees the error and can manually retry, rather than looping infinitely.
- **Type unification:** `error.rs` re-exports `BlockPos`, `ToolType`, `MaterialTier` from `types.rs` — no duplicate definitions. `ToolType` has 7 variants (Pickaxe, Axe, Shovel, Hoe, Sword, Shears, Hand). No `to_error_*` bridge helpers needed.
- **Snapshot building:** `handle_tick` delegates to `SnapshotUpdater::update_from_tick` — the inline `build_and_update_snapshot` and helper functions were deleted from `events.rs` to avoid duplication with `snapshot_updater.rs`.
- **Mutex poisoning recovery**: Extended from `SharedState` to all shared mutexes (including `channel.rs` command receiver slot, `bot/events.rs` executor handle, and `logging.rs` test helpers). All use `.unwrap_or_else(|e| e.into_inner())` to prevent cascade crashes.
- **`SharedState::modify_snapshot` 约定:** 事件 handler 更新快照部分字段（entities / self_player.health 等）**必须**用 `SharedState::modify_snapshot<F: FnMut(&mut WorldSnapshot)>(&self, f: F)`，基于 `ArcSwap::rcu` 原子读-改-写。闭包签名为 `FnMut(&mut WorldSnapshot)`（**不是 `FnOnce`**，因为 `rcu` 在并发更新下可能重试）。**禁止**再用 `read_snapshot().clone()` + `update_snapshot()` 模式 —— 该模式会丢更新（`SnapshotUpdater` 在 await 点交错时会把字段原样写回，抹掉事件 handler 的修改）。`handle_death` / `add_player_to_snapshot` / `handle_remove_player` / `handle_update_player` 已迁移到此 API。
- **`command_sender` 注入链路约定:** `Act::Mine` 需要委托 `CompoundOpExecutor` 完整执行（选工具→走过去→挖掘→验证）。由于 azalea ECS 通过 `BotState::default()` 构造 `BotState`，无法直接传参，采用与 `INJECTED_SHARED_STATE` / `INJECTED_COMMAND_RECEIVER` 同模式的 `Mutex<Option<T>>` 注入：`ConnectionManager::connect(command_receiver, egui_ctx, command_sender)` 在重连 `loop` **内部**（C-2 修复）每次迭代 `events::INJECTED_COMMAND_SENDER.set(Some(command_sender.clone()))`；`BotState::default` 读取该 static 得到 `command_sender: Option<BotCommandSender>`；`handle_spawn` 在 `async move` 闭包**外**提前 `let command_sender = state.command_sender.clone();`（避免 E0521 borrowed data escapes）传入 `CommandExecutor::new_for_lease(client, shared_state, command_sender)`；`CommandExecutor::sender: Option<BotCommandSender>` 标注 `#[allow(dead_code)]` —— **C-1 修复后 `handle_act` 不再使用 `sender` 字段**，仅保留以免改动 `connect` 调用链；`handle_act(Mine)` 现在直接把 `self`（`&CommandExecutor`）传给 `CompoundOpExecutor::execute_mine_block(self, pos, true)`，`CompoundOpExecutor` 已重构为单元结构 + 关联函数（`fn execute_mine_block<B>(executor: &CommandExecutor<B>, pos, verify) -> ...`），通过 `executor.dispatch(cmd)` 直接派发子命令而非走 `BotCommandSender` 通道（旧实现会在单消费者执行器循环上自死锁）。递归调用链 `dispatch → handle_act → execute_mine_block → dispatch` 通过在 `handle_act` 内用 `Box::pin(execute_mine_block(...))` 包装解决 E0733（async fn 递归）。`INJECTED_COMMAND_SENDER` 仍按 C-2 在 `connection.rs::connect` 的 `loop` 内每轮重新 set（不再被 `CompoundOpExecutor` 消费，保留供未来用途）。`MinecraftApp` 持有 `sender: BotCommandSender` 字段（来自 `main.rs` 的 `sender_for_egui`），`connect_bot` clone 一份传入 `manager.connect(...)`。
- **`shutdown_token` 生命周期约定:** `SharedState` 持有 `shutdown_token: Mutex<CancellationToken>`（来自 `tokio-util`，与 `cancel_token` 字段独立 —— `cancel_token` 用于打断 reconnect backoff sleep，`shutdown_token` 用于 MCP graceful shutdown，两者生命周期独立）。通过 `shutdown_token() -> CancellationToken` 暴露（克隆返回）、`trigger_shutdown()` 触发。`MinecraftApp::drop` 调用 `trigger_shutdown()`；`serve_http` 在 `app` 构造前 `let shutdown_token = state.shutdown_token();`（因为 `.with_state(state)` 消费 state），再用 `axum::serve(listener, app).with_graceful_shutdown(async move { shutdown_token.cancelled().await; })`（**必须用 `async move` 包装** —— `CancellationToken::cancelled()` 返回的 future 借用 token，非 `'static`，不满足 `with_graceful_shutdown` 的 `Send + 'static` 约束）；`serve_stdio` 在 `McpBotServer::new(state, sender)` 前 `let shutdown_token = state.shutdown_token();`，再用 `tokio::select!` 并联 `running.waiting()` 与 `shutdown_token.cancelled()`，shutdown 触发时立即返回不等 stdin EOF。MCP 线程 `JoinHandle` 现存于 `MinecraftApp`，drop 时 join（3 秒超时，与 bot 线程一致）。
- **`tick_abort_handles` 约定:** `BotState` 新增字段 `tick_abort_handles: Arc<Mutex<Vec<AbortHandle>>>`，追踪 `handle_tick` 中 `spawn_local` 的 tick 任务 `AbortHandle`。`handle_disconnect` 时 abort 全部并清空，防止 ECS 拆除后 tick 任务调用 `bot.component()` / `bot.world()` 触发 panic 或写入陈旧快照。模式与 `executor_handle` 一致（`take()` + abort）。
- **Command timeout:** `BotCommandSender::with_timeout` honours `AppConfig::command_timeout_secs`; `main.rs` wires the configured value at startup.
- **UI i18n:** Functional, one-file-per-language module under `src/ui/i18n/`. `Language` enum (`En`, `ZhCn`) with `Default = En`; `TextKey` enum enumerates all UI strings; `tr(key) -> &'static str` is a pure dispatch to the current language's `lookup`. Current language is held in a `static RwLock<Language>` (`current()`/`set()`). `AppConfig::language` persists the choice (`#[serde(default)]` for backward compat). The Settings panel Language dropdown calls `i18n::set()` on change for next-frame effect (no reconnect). MCP tool descriptions and JSON field names stay English (external API contract).
- **CJK fonts:** `src/ui/fonts.rs::install_system_cjk_fonts(ctx)` probes the platform default CJK font (Windows `msyh.ttc`, macOS `PingFang.ttc`, Linux Noto/WenQuanYi) at startup and injects it into egui `FontDefinitions` (appended to `Proportional` and `Monospace` as a fallback — see R-3). Falls back to the default font with a `warn` log if none found — never panics. Called once in the eframe creation closure.

Artifacts named `minecraft-mcp-rs-<os>-<arch>`. - **Block-update packets (M-2):** `Event::Packet(Arc<ClientboundGamePacket>)` is the catch-all for game packets — azalea 0.15.1 has no dedicated `BlockUpdate` event variant. `handle_event` matches `Event::Packet(packet)` and dispatches to `handle_packet_block_updates(state, &packet)`, which pattern-matches `ClientboundGamePacket::BlockUpdate(data)` → `dirty_tracker.mark_block_dirty(data.pos)` and `ClientboundGamePacket::SectionBlocksUpdate(data)` → iterates `data.states` and computes each block's world `BlockPos` via `data.section_pos + entry.pos` (azalea-core provides `impl Add<ChunkSectionBlockPos> for ChunkSectionPos`). All other packet variants are ignored. The tracker lock uses `.unwrap_or_else(|e| e.into_inner())` for poisoning recovery. Without this handler, single-block updates from the server (block break/place by other players, piston extension, water flow) would never mark the snapshot dirty and the bot would see stale world state.
- **`find_standable_neighbor` (M-4):** `execute_mine_block` must NOT use the target block's own position as the `MoveTo` destination — the bot would path into the block and get stuck. Instead, call `compound_ops::find_standable_neighbor(&snapshot, target_pos)` which scans the 8 horizontal neighbours × 3 Y levels (priority: same Y → y+1 → y-1) and returns the first air block with a solid block below it. Block lookups go through `WorldSnapshot::block_index` (M-12) — O(1) per check, not O(N) linear scan. If no standable neighbour exists, the state machine transitions to `Failed(PathfindingFailed { move_target: target_pos })` rather than attempting an unreachable path.
- **`WorldSnapshot::block_index` (M-12):** `WorldSnapshot` carries a `block_index: HashMap<BlockPos, usize>` (`#[serde(skip)]` — derived from `blocks`, not part of the MCP JSON contract). `SnapshotBuilder::build` constructs it via `blocks.iter().enumerate().map(|(i, b)| (b.position, i)).collect()`. Code that needs to look up a block by position MUST use `snapshot.block_index.get(&pos)` → `&snapshot.blocks[idx]` rather than `snapshot.blocks.iter().find(|b| b.position == pos)` — the index is O(1), the linear scan is O(n) and was a hotspot for large snapshots. New `WorldSnapshot` literals must add `..Default::default()` (or `block_index: HashMap::new()`) since the field is non-optional. **`execute_mine_block` MUST go through `block_index` in both Step 2 (look up the target block's `block_type` to choose a tool) and Step 10 (verify the block was actually broken by re-reading via `block_index.get(&pos).is_none()`).** Linear `Vec::iter().find()` lookups inside the state machine are forbidden — they make the hot path O(n) per tick and have repeatedly regressed this code path. Regression test: `test_mine_block_uses_block_index` with a 5000-block snapshot must complete in < 1 ms.
- **`McpServerStatus` (M-13):** `SharedState` exposes `mcp_server_status: Mutex<McpServerStatus>` with `set_mcp_server_status()` / `get_mcp_server_status()`. `serve_http` calls `set_mcp_server_status(Running(addr))` after a successful bind, `Failed(msg)` on bind failure (also calls `set_last_error`), and `Stopped` when the server exits. `serve_stdio` calls `Stdio` at start and `Stopped` at end. The Status panel renders the current value so users can see whether the MCP server is up, where it's listening, or why it failed — without checking the terminal.
- **First-connect retry (M-9):** `ConnectionManager::connect` retries the first connection (`!was_online`) up to `MAX_FIRST_CONNECT_RETRIES = 3` times with a 2-second interval before falling through to fail-fast. This handles transient DNS / network blips on startup without entering an infinite retry loop. The retry sleep races `cancel_token()` so a disconnect request aborts immediately. Subsequent reconnects (after the bot was online) remain fail-fast — only the very first connection gets the retry window.
- **HTTP TLS warning (M-8):** when `mcp_transport == McpTransport::Http` AND `mcp_address` is not in `["127.0.0.1", "::1", "localhost"]`, both the Settings panel (below the Bind Address input) and the MCP Config panel render a red warning: "⚠ No TLS — use trusted network or reverse proxy". This reminds users that MCP HTTP transport has no encryption and should be put behind a TLS-terminating reverse proxy (e.g. nginx) when binding to a non-loopback interface.
- **`Offline` vs `CommandTimeout` semantics (S-4):** `BotCommandSender::send_command` distinguishes two failure modes: (1) `BotError::Offline("bot command channel closed")` — the receiver was never there or has been dropped; (2) `BotError::Offline("bot command responder dropped without reply")` — the receiver accepted the command but dropped the oneshot responder without replying (executor aborted/panicked mid-command). The third mode, `BotError::CommandTimeout`, is reserved for the genuine "responder is alive but slow" case (the `tokio::time::timeout` branch). Previously the responder-dropped case was incorrectly classified as `CommandTimeout`, hiding the fact that the bot was gone rather than merely slow. Tests asserting "responder dropped → Offline" live in both `src/channel.rs::tests::test_offline_when_responder_dropped` and `tests/integration.rs::test_offline_returned_when_responder_dropped*`. **MCP error mapping (Offline → -32000 SERVICE_UNAVAILABLE):** when `BotError::Offline(_)` is converted to MCP `ErrorData` (via `From<BotError> for ErrorData` in `src/error.rs` AND the `IntoCallToolResult` impl), the resulting JSON-RPC code MUST be `-32000` (JSON-RPC "server error" range, semantically `SERVICE_UNAVAILABLE`) — NOT the generic `-32603 InternalError` it was previously mis-mapped to. The error data field carries `serde_json::json!({"reason": "bot_disconnected"})` so MCP clients can distinguish "bot is gone, retry later" from "input is invalid" (`-32602`) and from "internal server error" (`-32603`). Both `test_into_mcp_error_offline_uses_service_unavailable` (the new assertion) and the updated `test_into_mcp_error_offline` (asserting the `reason` payload) live in `src/error.rs::tests`.
- **Lazy command logging (S-5):** `send_command` clones `cmd` into `cmd_for_log` and uses `tracing`'s `?cmd_for_log` lazy formatting (`trace!(command = ?cmd_for_log, ...)`) so the `Debug` formatting is only paid when the log level is enabled. The previous `format!("{:?}", cmd)` ran unconditionally on every call. The `format!` is now only in the `CommandTimeout` error path (which needs an owned `String` for the error variant).

- **Harvest Level (H-1):** vanilla Minecraft's tool tier system is enforced. `block_data::HARVEST_LEVEL: HashMap<&str, u8>` maps a block's required harvest tier: `Wood=0, Stone=1, Iron=2, Diamond=3, Netherite=4` (lower numbers are weaker). `tool_select::find_tool_in_inventory` now takes a `required_harvest_level: u8` parameter; any tool whose own `ToolMaterialTier < required` is rejected as `None` (NOT optimistically selected). The table covers at minimum `Stone` (→Iron, 2), `Cobblestone` (→Iron, 2), `IronOre`/`DeepslateIronOre` (→Stone, 1), `DiamondOre`/`DeepslateDiamondOre` (→Iron, 2 — needs iron pick to harvest the ore block, then drops diamond; some sources say stone is enough to break but no drops, iron guarantees the drop), `Obsidian` (→Diamond, 3), `AncientDebris` (→Diamond, 3), and `NetheriteBlock` (→Netherite, 4). When `find_tool_in_inventory` returns `None`, the caller MUST surface a `BotError::ToolNotFound { alternatives: [<next-tier tool name>] }` (e.g. "use an Iron Pickaxe to mine Diamond Ore") so the LLM client can tell the user to upgrade. **木镐不能挖钻石矿** (wood pickaxe cannot mine diamond ore — the best tool is silently downgraded, which loses resources and the player does not know why). Regression tests: `test_harvest_level_wood_cant_mine_diamond` (asserts `None` + `alternatives: ["IronPickaxe"]`) and `test_harvest_level_diamond_mine_diamond_ore` (asserts `Some(DiamondPickaxe)`). `mining_calc::calculate_mine_time` is unaffected — harvest level is a gate, not a speed multiplier.
- **`ClearGuard` for `bot_connecting` (R-1):** `src/ui/app.rs` defines `ClearGuard<'a>(&'a SharedState)` whose `Drop` calls `state.clear_connecting()`. The bot connection thread wraps its body with `let _clear_guard = ClearGuard(&state);` as the first statement after `spawn`. This RAII guard ensures that **even if the thread panics** (unwinding calls `Drop`), the `bot_connecting` flag is cleared. Without this, a panic in `Runtime::new()` or any other early failure before the explicit `state.clear_connecting()` at the bottom of the thread would leave the flag permanently `true`, blocking all subsequent Connect attempts. The guard is safe during unwinding because it only touches an `AtomicBool`.
- **`MinecraftApp::last_language` (R-2):** `MinecraftApp` caches `last_language: Language` to deduplicate per-frame `read_config` acquisitions for language synchronisation. The `ui()` method compares `self.last_language` against `self.state.read_config().language` and only calls `i18n::set()` on mismatch. This replaces a per-frame `RwLock::read()` that fired unconditionally even when the language hadn't changed.
- **CJK fonts now appended (R-3):** the system CJK font is *appended* (not prepended) to `egui::FontFamily::Proportional`, so Latin glyphs consistently use the primary font (Ubuntu-Light) and non-Latin glyphs fall through to the CJK font as a last resort. egui 0.34 searches all fonts in the family list, so appending is sufficient for correct CJK rendering.

This matches the `#[schemars(range(min = 1, max = 100))]` JSON Schema contract. Previously, a malicious client could pass `radius=u32::MAX` and trigger pathological O(n) scans or integer-overflow-based incorrect results.
- **`clamp_to_i32` for all u32→i32 conversions (R-5):** `command_validate::clamp_to_i32` clamps a `u32` to `i32::MAX` rather than silently truncating via `as i32` (which wraps to negative for values > `i32::MAX`). - **Container tool validation order (R-6):** `handle_take_from_container` and `handle_put_into_container` validate `count == 0` *before* the `check_container_open` / `is_online` gate, so a malformed parameter always yields `InvalidParams` rather than a misleading state-dependent error. - **`handle_collect_items` naming (R-7):** the local variable and JSON field are named `visited` (not `collected`) because `goto` success only guarantees the bot *reached* the item's position — the server may not have processed the pickup. - **`handle_place_block` result message (R-8):** `"slot:N"` internal prefixes are stripped from the result message via `block_type.strip_prefix("slot:").unwrap_or(&block_type)` so the LLM sees a clean block type name rather than an opaque hotbar index.
- **`equip_tool` material preference wiring:** `EquipToolInput.material_preference` is now honoured (previously it was echoed into the response JSON but never affected tool selection). `tools_item::parse_material_tier` maps the string (case-insensitive; `wooden`/`golden` aliases accepted) to a `MaterialTier`; an unknown value returns `InvalidParams`. When present, the MCP handler sends the new `BotCommand::EquipToolWithMaterial(ToolType, MaterialTier)` instead of `EquipTool(ToolType)`; both route to `handle_equip_tool(tool, Option<MaterialTier>)`, which converts the tier to a minimum harvest level via `block_data::harvest_level_of` and passes it to `tool_select::find_tool_in_inventory`. Semantics are **minimum tier** (request Diamond → accept diamond/netherite, reject lower); requesting a tier above every matching tool yields `ToolNotFound`. - **Centralized command validation (dispatch gate):** `CommandExecutor::dispatch` calls `crate::command_validate::validate_command(&cmd)?` as its first statement (before the online check) so every command — including those generated internally by `CompoundOpExecutor` — is bounds-checked in one place. - **`SelfPlayer::position_precise` and `yaw` (W-1):** `SelfPlayer` in `types.rs` carries two `#[serde(skip)]` fields — `position_precise: Option<[f64; 3]>` (sub-block-precision player position, populated by `SnapshotUpdater` from `azalea::entity::Position`) and `yaw: Option<f32>` (horizontal look direction, populated from `azalea::entity::LookDirection::y_rot()`). - **World view cache (W-2):** `SharedState` has a `last_world_view: Mutex<Option<WorldViewCache>>` for caching the most recent `get_world_view` render. - **Section-level chunk scanning (W-3):** `build_snapshot_inner` in `snapshot_updater.rs` now scans dirty chunks section by section (16×16×16 per section, 24 sections per chunk) instead of the previous flat 3× for loop. Before scanning each section, the chunk's `sections[].block_count` is read: if it is `0` (entirely air), the section's 4096 `get_block_state` calls are skipped. For typical surface chunks this skips ~23/24 sections, reducing the per-chunk scan from 98304 calls to ~4096 (only the surface section). The chunk read lock is held briefly to build `sections_to_scan: Vec<usize>`, then released before the per-block scan (which acquires its own lock through `world_guard.chunks.get(&chunk_pos)`).

The MCP Config panel omits the `Authorization` header from the generated JSON entirely when auth is off (never leaks the token). Tests for the pure `is_request_authorized` decision and the auth-off config JSON live in `src/mcp/server.rs::tests` / `src/ui/mcp_config.rs::tests`.
- **Headless mode & CLI (S-10):** `src/cli.rs` uses **clap 4.6 (derive)** — `CliArgs` carries `--headless`/`--gui`/`--stdio`/`--config <path>` plus clap-provided `-h/--help` and `-V/--version`; `parse_cli_args()` = `CliArgs::try_parse()`; `main` prints `DisplayHelp`/`DisplayVersion` errors to **stderr** and exits 0, usage errors to stderr and exits 2 — **stdout is never touched** (MCP transport). `print_help` renders clap's help (`CliArgs::command().render_help()`) to stderr. `cli::resolve_mode` keeps the fixed precedence: **no arguments at all prints help and exits 0**; `--headless` wins over `--gui`; `--stdio` alone implies Headless (Option B — the MCP client's stdin/stdout is the whole app); `--gui` explicitly opens the desktop window, and `--config <path>` alone resolves to Gui. `main.rs` loads config via `load_from_disk`, forces stdio on `--stdio`, and in headless mode spawns a `headless_supervisor` thread (in `bot/spawn.rs`) that auto-connects, re-spawns after `config_restart_requested` (consumed once via `headless_next_action`), and exits when `shutdown_token` is cancelled. **The MCP thread calls `trigger_shutdown()` after the transport closes in headless mode** — stdio client gone → process exits. The supervisor polls `is_finished()` rather than blocking on `join()`, and on shutdown aborts the bot's in-flight connect attempt via `request_disconnect()` (else a dead server keeps the process alive through azalea's TCP retries). The MCP Config panel's local-executable snippet passes `["--stdio"]` so a bare `minecraft-mcp-rs` invocation in an MCP client never hits the no-args help+exit path.
- **Bot thread handle ownership (S-11):** the bot thread's `JoinHandle` lives in `SharedState` (`store_bot_thread_handle`/`take_bot_thread_handle`), set by `spawn_bot_connection`. `MinecraftApp::drop` and the headless supervisor both take + `join_with_timeout` (now `pub` in `bot/spawn.rs`, 3 s bound). `join_with_timeout` is shared by UI and headless paths.
- **Error-code table (S-12):** every `BotError` variant maps to a distinct JSON-RPC code + structured `data` (`reason`, `retryable`, variant fields). Custom codes `-32000`..`-32008` are named `CODE_*` constants in `src/error.rs` above a doc-comment table; `BlockNotFound` → `RESOURCE_NOT_FOUND` (-32002), `ToolNotFound`/`TooFar`/`InvalidParams` → `INVALID_PARAMS` (-32602), `PermissionDenied` → `INVALID_REQUEST`, `Internal` → `INTERNAL_ERROR`. `ToolNotFound` keeps its REQUIRED `alternatives: Vec<String>` field. New variants must get a mapping arm + a dedicated mapping test.
- **npm layout (S-13):** `npm/` holds the main package `minecraft-mcp-rs` (UNscoped — bin shim `bin/minecraft-mcp-rs.js`, `optionalDependencies` on 5 platform packages, no os/cpu) + 5 platform packages `@minecraft-mcp-rs/minecraft-mcp-rs-{windows-x64,windows-arm64,darwin-arm64,linux-x64,linux-arm64}` (scoped under the npm org; os/cpu fields; binaries staged by CI, `.gitignore`d locally; directory names stay unscoped, the scoping lives in each package.json's `name`). `npm/scripts/sync-versions.mjs` stamps the Cargo.toml version into every package.json and the main package's optionalDependencies (run it after bumping Cargo). `.github/workflows/release.yml`'s `npm-publish` job publishes platform-first then main with `--provenance` (which requires `id-token: write` + GitHub-hosted runner), skips already-published versions, and authenticates via npm Trusted Publishing (OIDC — each package on npmjs.com → Settings → Trusted Publishers → GitHub Actions, owner `halfoffive`, workflow `release.yml`) OR the `NPM_TOKEN` secret (granular token, NEVER commit it; used via `NODE_AUTH_TOKEN` when present). Run snippets pin an exact release. The UI MCP Config panel derives the pin from `env!("CARGO_PKG_VERSION")` via `npm_package_pin()` in `src/ui/mcp_config.rs` (`minecraft-mcp-rs@<version>`), so it can never drift from Cargo; markdown docs (README.md, npm/*/README.md, docs/npm.md + zh mirror) use a literal `@1.3.0` pin. npx needs `-y` to skip the install prompt; bunx auto-installs without prompting, so no `-y`. **When bumping the Cargo/npm version, update every literal `@<version>` pin in the markdown docs AND the MC compatibility table** (`env!` and `npm/scripts/sync-versions.mjs` keep code and npm in sync automatically; markdown does not).
- **Entity rebuild convention (S-14):** `SnapshotUpdater` owns `entities` — it rebuilds them from the live ECS on every snapshot build. Event handlers (`add_player_to_snapshot`, `handle_remove_player`, `handle_update_player`) must NOT push/remove entities in the snapshot; they only touch `self_player` via `modify_snapshot`. Item drops are emitted with `entity_type` matching the `collect_items` filter (snake_case via `utils::to_snake_case`).
- **Single Minecraft version (S-15):** the tool supports **only Minecraft Java Edition 1.21.11** (via azalea 0.15.1) — no multi-version support. A server-version → tool-version compatibility table (1.21.11 ↔ 1.1.3) lives in README.md (bilingual callout), docs/guide/getting-started.md + zh mirror, and docs/npm.md + zh mirror. When the MC target or tool version changes, update the table in all four places and every markdown `@<version>` pin in the same change.
- **Release pipeline & version bumps (S-16):** the CI split is fixed: build.yml on `develop` runs the run-once checks (`cargo fmt --check` → `cargo clippy --locked --all-targets -- -D warnings` → `cargo test --locked --all-targets`) plus the dev matrix build (PRs run lint only); `release.yml` then performs ONLY `--release` builds + publish — `release` and `npm-publish` both `needs: [build, mode]` (npm's publish loop skips already-published versions — "publish if needed" needs no manual gate). **Batch git commits (per Development workflow):** work on a branch and commit in separate atomic commits — (a) CI workflows, (b) AGENTS.md conventions, (c) Cargo+npm version bump, (d) markdown pins/tables, (e) CHANGELOG — then push the branch, open a PR, wait for **user review**, merge to `master`, then create+push the `v*` tag (`release.yml` fires on tag push only). **Version-bump procedure (same change; see S-13 for the pin rule):** bump `Cargo.toml` → run `node npm/scripts/sync-versions.mjs` → update every markdown `@<version>` pin AND the MC compatibility tables in the same release → add a `## [X.Y.Z] - <date>` CHANGELOG section → branch → PR → user review → merge → tag `vX.Y.Z` → GitHub Release + npm publish auto-run (npm skips already-published).
- **azalea inventory slot ordering invariant (hotbar):** azalea's `Menu::Player.inventory` (and the trailing 36 player slots of every container menu, read via `Menu::player_slots_range()`) is laid out in *protocol* order — **main inventory first (indices 0-26), hotbar last (indices 27-35)** — while the rest of the crate assumes the canonical **hotbar-first** order (0-8 = hotbar, 9-35 = main). `src/bot/commands.rs` exposes `canonical_inventory_slot(azalea_slot) -> usize` and `canonical_player_inventory(&Menu) -> Vec<Option<ItemStack>>`, the **single** place that reconciles the two; `RealBotClient::inventory_entries` and `snapshot_updater::read_inventory` must both go through it (never `try_as_player()`, which returned an empty list while a container was open). `equip_tool`, `drop_item`, `MoveItemToHotbar`, and `select_tool_for_block` all assume hotbar-first and are only correct because this helper normalizes first. When `equip_tool` finds the tool only in the main inventory it now auto-moves it into the first free hotbar slot (via the `MoveItemToHotbar` swap) instead of erroring. Regression tests: `test_canonical_inventory_slot_reorders_hotbar_first`, `test_equip_tool_moves_from_main_inventory` in `bot/commands.rs::tests`.
- **`fly_to` vertical movement (azalea ground-only pathfinder):** azalea 0.15.1's pathfinder only walks/jumps/falls — it cannot change the player's Y beyond a 1-block jump, and there is no creative-flight move. `handle_fly_to` therefore splits the flight: a horizontal `goto` leg to `(target.x, current.y, target.z)`, then a direct position update via `BotActions::teleport` for the vertical delta (safe in Creative: no fall damage, no collision for the bot's own body). A horizontal `goto` failure is reported as `obstacle` and does **not** teleport past the blockage. Regression tests: `test_fly_to_vertical_reaches_target`, `test_fly_to_blocked_horizontally_does_not_teleport` in `bot/commands.rs::tests`.
- **`act` per-call perception radius:** `BotCommand::Act(ActAction, Option<u32>)` carries a per-call perception radius (0..=32, validated in `command_validate::validate_command` and `tools_act::handle_act`); `None` falls back to `AppConfig::block_perception_radius` (default 32, whose full ActResult serialises to >1 MB). `handle_act` filters both `nearby_blocks` and `nearby_entities` by the same Chebyshev radius; `Some(0)` strips the nearby context entirely. New `BotCommand::Act` call sites MUST pass the second tuple element — the exhaustive matches (dispatch, `validate_command`, `count_variants`/`require_all_variants`, types/integration tests) will fail to compile otherwise. Regression tests: `test_act_perception_radius_trims_nearby_context` (`bot/commands.rs::tests`), `test_act_passes_perception_radius_through` / `test_act_rejects_oversized_perception_radius` (`tools_act.rs`).
- **`smart_move` single retry on transient obstacles:** `handle_smart_move` loops once: when the first `goto_with_margin` ends unreached (Ok-but-far or pathfinder Err — e.g. the grass block underfoot misreported as an obstacle), it sleeps `SMART_MOVE_RETRY_DELAY` (300 ms) and retries once; `TimedOut` is never retried (it already spent the window). Every result carries `"retried": bool` in `data`. The message contract is preserved: Err → "SmartMove to {target} blocked: {e}", Ok-unreached → "SmartMove to {target}: obstacle". Mock support: `goto_failures_remaining` (transient-failure counter) and `bind_state` + `goto_updates_snapshot` (successful goto moves the shared snapshot's player position via `modify_snapshot` — default off, use `make_executor_with_snapshot_goto` in tests that re-read the snapshot after movement). Regression tests: `test_smart_move_retries_once_and_reaches_target`, `test_smart_move_retries_once_then_reports_obstacle` in `bot/commands.rs::tests`.
- **`attack_entity` auto-approach (moving targets):** `handle_attack_entity` is async: when the target is farther than `MAX_ATTACK_REACH` (6.0), it `goto_with_margin`s to the entity's last known position (timeouts also fall through), then re-reads the snapshot and attacks only if the entity is within reach NOW — a moving target that got away yields an honest `TooFar` (caller should re-run get_nearby_entities → move_to → attack); a despawned target yields `InvalidParams` ("no longer in the world snapshot"). Reach math goes through the free helper `distance_between(BlockPos, BlockPos) -> f64`. Tests: `test_attack_entity_auto_approaches_when_too_far`, `test_attack_entity_too_far_reports_too_far_after_approach` in `bot/commands.rs::tests`.
- **`use_item_on_block` reports the item actually used:** the result message is `"Used {item} on block at {pos} (slot {n})"` where the item comes from the snapshot inventory at `item_slot` (or `held_item_slot` when `None`); empty slot → "empty". This makes a wrong-slot interaction (the smoke test's water-bucket failure) visible. Test: `test_use_item_on_block_reports_item_used` in `bot/commands.rs::tests`.

- **Prerelease pipeline (release branch):** `.github/workflows/release.yml` has two channels — push to `release` → **pre-release** (GitHub Release `prerelease: true` + npm dist-tag `next`); tag `vX.Y.Z` on `master` → **stable** (GitHub "Latest Release" + npm `latest`). A `mode` job decides the channel: prerelease iff branch push / tag name contains `-` / tag `base_ref` is `release` / `workflow_dispatch` input `prerelease=true`; `npm_tag` = `next` : `latest`. On branch pushes the `release` job derives the tag from `Cargo.toml` (`v` + version) and skips when the release already exists (`gh release view` guard); `npm-publish` uses `--tag` from the mode output and keeps the skip-if-published loop — re-pushing `release` with an unchanged version is therefore idempotent. Branch-model docs live in `CONTRIBUTING.md`; `release/<X.Y.Z>` branch names are FORBIDDEN (refs namespace conflict — the old `release/1.2.0` branch was deleted when this model was adopted).
